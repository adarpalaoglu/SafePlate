# Data Directory

Pre-computed data files are included in the submission so markers can run the application immediately after installing dependencies, without waiting for data processing (embedding training in particular takes significant time).

All files can be regenerated from scratch using:

```bash
python backend/scripts/prepare_data.py --force-all --verbose
```

## Directory Structure

### `raw/`

Contains `RAW_recipes.csv` (281 MB), the original Food.com dataset (~230K recipes). This file is the sole input to the data pipeline.

### `processed/`

Generated by `prepare_data.py`. Only files actually used by the application are included:

| File | Description |
|------|-------------|
| `recipes_cleaned.csv` (289 MB) | Cleaned recipes with normalised ingredient lists |
| `recipe_ingredients.csv` (52 MB) | Recipe-to-ingredient mapping (one row per recipe) |
| `ingredient_vocabulary.csv` | Canonical ingredient list with frequency counts |
| `ingredient_groups.csv` | Ingredient-to-group mapping (food taxonomy) |
| `ingredient_cooccurrence_edges.csv` | Pairwise ingredient co-occurrence weights |
| `cleaning_metadata.json` | Pipeline run metadata (row counts, timestamps) |

### `processed/embeddings/`

Contains the production Node2Vec embedding file loaded by the app:

```
ingredient_node2vec_iter10_UNWEIGHTED_p1_q4_w10_wl80_r80_e10.txt
```

### `user_preferences.json`

Persisted user ingredient rankings (created/updated at runtime by the preference system).
